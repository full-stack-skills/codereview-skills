# 修复回路示例

```text
问题：重复通知可能再次写入 outbox。
测试（修复前）：同一 event_id 两次调用只产生一条出库记录；实际产生两条，失败。
最小修复：在事务内对 event_id 做唯一性判定，重复事件返回已有处理结果。
测试（修复后）：目标测试通过；订单模块回归通过。
重新审查：新候选指纹 7df…；原指纹 2a1… 的 OCR 报告标为 stale，新报告未再发现该路径问题。
未验证：真实消息系统重放未执行。
```

## 部分暂存陷阱

插件审查的是索引快照，修复可能只改工作区。不要把工作区测试通过当成“候选提交已修复”；要核对 `git diff --cached` 或插件的新候选指纹。是否暂存由用户当前提交意图决定，不自行把所有改动 `git add -A`。

## 建议代码陷阱

OCR 的 `suggestion_code` 只是建议。先核对类型、异常、并发和相关调用方；不要盲贴，也不要通过禁用规则来消除评论。
