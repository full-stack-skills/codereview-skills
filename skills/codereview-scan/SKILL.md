# OCR 全文件扫描

`ocr scan` 审查完整文件，适合接手旧系统、安全专项或指定目录审计；它与 Git diff 审查及插件提交候选快照是不同对象。用户说“审查这次提交”时不要默认扫描整个仓库。

## 什么时候使用与执行前检查

明确扫描范围：仓库、目录或具体文件；解释全仓扫描可能读取大量源码，不能用前一次提交审查授权替代。确认推理方、端点、模型和预算；不假设 Delegation Mode 支持 `scan`。检查当前 CLI 的 `scan --path`、输出文件和续跑能力，不自动升级。排除项必须在报告中可见。

## Workflow / 执行与报告

### Step 1 — 确定对象和外发边界
用户确认完整仓库或指定路径后，记录路径、排除项、推理方、模型及预算。若模型/端点不可确认，停在计划，不执行扫描。

### Step 2 — 执行或续跑
对同意范围运行 `ocr scan --path <path>`；供宿主读取时使用当前 CLI 支持的机器可读输出/文件选项。中断后先查会话，仅同一范围和版本才用 `--resume <session-id>`。

### Step 3 — 核实与覆盖
逐条核实高风险发现，区分已证实和待验证。保留 skipped/failed/budget 与文件数量；空 findings 不等于无风险。

### Step 4 — 交付
输出审查范围、引擎/模型、执行状态、覆盖统计、重点发现和未扫描区域。结果不适用于后续修改后的提交。

场景选择与输出样例见 [扫描决策表](references/scan-scenarios.md)。

## 不适用

PR、分支、单提交和普通工作区差异优先使用官方 `open-code-review`；提交前用户授权与暂存快照使用插件专属 `codereview-harness`；可执行依赖/凭据检查仍由 CodeGuard 完成。

## Gotchas / 易错点

- 旧仓库全文件扫描可能显著增加费用；先确定目录和预算。
- `scan` 与 `review` 的续跑参数不能混用。
- 生成文件和第三方源码若被排除，报告必须显式说明。
- 扫描完成后的新提交不在原报告覆盖范围内。
