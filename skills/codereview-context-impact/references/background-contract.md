# 背景与影响模板

## 示例：订单状态变更

```text
审查对象：feature/order-retry 相对 main 的 merge-base 差异
业务目的：重复支付通知只能产生一次出库任务（来源：openspec/specs/order-notification/spec.md）
必须保持：
1. 同一 payment_id 重放不增加出库次数（正式规格）
2. 已取消订单不回到待出库（状态机测试）
3. 下游超时重试不会覆盖已完成记录（消费者实现，待测试核实）
影响路径：WebhookHandler → OrderApplicationService → outbox → InventoryConsumer
重点风险：事务提交前发布消息；幂等键在重试路径丢失
未知与覆盖：未见线上重放样本，第三项为待核实假设
```

## 给 OCR 的输入

手动 OCR 审查可将经过删减的摘要交给 `--background` 或私有 `--background-file`。不要将凭据、完整用户数据或未经同意的邻接仓库源码放入背景。背景文件存在大小限制时先生成忠实摘要；不能忠实压缩就不传背景，改由宿主在授权范围内阅读原材料。

## 容易出错的地方

- 把当前工作区内容当成插件候选快照；两者可能不同，尤其是部分暂存。
- 将测试名称当成需求证据；测试可能落后或只覆盖正常路径。
- 从调用图可达推断一定执行；动态分派、特性开关和条件分支还需代码证据。
- 将“可能影响”写成“已破坏”；审查背景是待验证假设，不是发现。
